Three traps hit during submission, recorded so nobody repeats them:

1. **App Store Connect refuses Xcode-managed bundle IDs.** Symptom: the Bundle ID
   dropdown silently resets to "Choose". Fix was registering an explicit App ID
   (`com.terraxtech.app`) in the developer portal.
2. **`sips` keeps the source encoding regardless of the output filename.** PNG-named

If Apple rejects, the fix loop is: change code → bump build number in
`pubspec.yaml` → `flutter build ipa --release` → upload via Transporter → attach
the new build on the version page → resubmit.

## 4. Known bugs shipped in 1.0

**Ambient light scene modes.** On the LAMP&FRGN car ambient light, modes **Sports
through Winter sonata** (ids 6-18) all play the same generic blink instead of
their own animation. Everything outside that block is correct. Nothing in either
store listing promises those specific animations, so shipping was honest, but it
is the top 1.0.1 candidate.

Already ruled out, so nobody repeats it: mode numbering is 0-based and confirmed
on hardware; `modeParam` 0 and 1 both fail; sweeping `mode1` 0-3 against `param`
0-7 from the in-app Calibration panel changes nothing.

**The next move** is to let the device tell us the answer. Set a scene like Sports
in the vendor LAMP&FRGN app, force-close that app so it releases Bluetooth,
connect in TERRAX TECH, and read **Calibration > Current mode (raw)**. That hex
string is exactly what the vendor app programmed. Worth checking first whether
that block even animates correctly *in the vendor app* — if it blinks there too,
this is a hardware or zone-setup issue, not a byte-encoding one.

**Secondary:** the ambient light takes roughly 20 seconds to relight after being
powered off. Power-on already sends colour before brightness; the next lever is
retrying frames the unit NACKs as busy right after waking.

## 5. Everything else worth knowing

- **Do not run `gem update`.** CocoaPods only installs on this Mac's system Ruby 2.6
  because several transitive gems are version-pinned. Updating breaks `pod`.
- **The app is free.** `kSubscriptionsEnabled` in `lib/billing/billing_config.dart`
  is `false`, so every gate is open, the paywall entry point is hidden, and no
  StoreKit call is made. The TERRAX Pro yearly subscription is fully built and
  tested behind that flag. To switch it on: sign Apple's Paid Apps agreement
  (banking and tax), create the `com.terraxtech.app.pro.yearly` product, flip the
  flag, ship an update. Note PHP 5/month is not offerable — Apple's floor in the
  Philippine storefront is around PHP 29.
- **Website deploys from `carreterodior/terrax-website`** (private) to Vercel team
  `terrax` → terraxgear.com. The Vercel Hobby plan **blocks deployments whose commit
  author is not the account owner**, so only Dior's own commits deploy. Local folder
  `~/terrax-website` is a copy that lags the repo; treat GitHub as the source of truth.
- **Detection matches on advertised service UUIDs, not just names**, because several
  accessories (the ambient light especially) advertise no name at all. Never claim
  service `0xAF30` for the ambient light — the rock lights advertise it too.
- **A duplicate device entry can shadow a working one.** If an accessory shows
  "Bad state: ... characteristic not found", it was added under the wrong protocol
  family. Long-press it on the home screen, remove, and re-add from a fresh scan.
