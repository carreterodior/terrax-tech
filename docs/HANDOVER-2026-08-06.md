## 2. What works on real hardware

Verified in the car on August 5-6.

- **Rock lights** (Triones family, `RZ-Slave-*`): colour, brightness, effects,
  and the new **Static - solid color** option that exits an animation.
- **Running board** (IntelliGo module B): extend, retract, pause, board light.
- **Car ambient lighting** ("Pocket Link CZH2-10", LAMP&FRGN family): detection,
  connect, colour, brightness, power off. This driver had never touched real
  hardware before this session.

### Known open issue: ambient scene modes

Modes **Sports through Winter sonata** (ids 6-18 in the vendor grid) all play
the same generic blink instead of their own animation. Everything outside that
block behaves correctly.

What has been ruled out, so nobody repeats it:

- Mode numbering is **0-based** (`mode2`), already corrected and confirmed by
  hardware. "Single color" and "Breathing" now play the right animations.
- `modeParam` 0 and 1 both fail. Sweeping `mode1` 0-3 and `param` 0-7 from the
  in-app Calibration section also fails; the block just blinks, sometimes in a
  different colour.

**The next move (not yet done):** use the vendor app as the answer key. Set a
scene like Sports in the LAMP&FRGN app, force-close that app so it releases the
Bluetooth connection, open TERRAX TECH, connect, and read the
**Calibration > Current mode (raw)** line. That hex string is exactly what the
vendor app programmed for that scene, which pins the encoding without guessing.
Also worth capturing the **Sub-mode ranges** line (the device's `0x0C` reply).

A useful prior question: does that block animate correctly **in the vendor app**?
If it blinks there too, this is a hardware or zone-setup issue, not a byte issue.

## 3. App Store launch status

### Decisions already made

- **Bundle ID is now `com.terraxtech.app`** (explicit App ID, registered in the
  paid team). The old `com.terrax.terrax` was Xcode-managed, and App Store
  Connect refuses those. That was the cause of the Bundle ID dropdown silently
  resetting to "Choose".
- **Monetization: TERRAX Pro, PHP 59 per year.** The originally requested PHP 5
  per month is not offerable: Apple's lowest price point in the Philippine
  storefront is around PHP 29.
- **Gating split** (implemented): free covers connecting, power, colour,
  brightness, and unlimited saved devices, so hardware a customer already bought
  is never bricked by a paywall. Pro unlocks animation effects with speed
  control, plus the advanced driver sections (Welcome, Climate, LEDs, Setup,
  Calibration).

### Code that shipped for this

| File | Role |
|---|---|
| `lib/billing/pro_service.dart` | Purchase, restore, entitlement. StoreKit is the source of truth; the local flag is only an offline cache. Store handle resolves lazily so tests never open a billing connection. |
| `lib/ui/paywall.dart` | Subscribe screen: price, renewal terms, Restore Purchases, terms and privacy links (all required by Apple guideline 3.1.2). |
| `lib/state/pro_providers.dart` | `isProProvider`, watched by the gated UI. |
| `test/pro_gating_test.dart` | Entitlement defaults, offline cache, product id guard. |

Product id is `com.terraxtech.app.pro.yearly` and **must** match the App Store
Connect product exactly. Changing that string orphans every existing subscriber.

### Build ready to upload

`build/ios/ipa/terrax.ipa` (about 23 MB) is built and signed with the paid team.
Rebuild any time with `flutter build ipa --release`.

### Remaining steps, all account-level

These need an Apple ID login or financial details, so they cannot be automated.

1. **Finish the New App record** in App Store Connect: name TERRAX TECH,
   Primary Language English (U.S.), Bundle ID `com.terraxtech.app`,
   SKU `terrax-tech-001`, Full Access.
2. **Sign the Paid Apps agreement** (Business > Agreements, Tax, and Banking),
   including bank and tax details. Until this is active, no subscription can
   carry a price and the product stays in "Missing Metadata". Account Holder
   only.
3. **Create the subscription**: group "TERRAX Pro", reference name
   TERRAX Pro Yearly, product id `com.terraxtech.app.pro.yearly`, 1 year,
   PHP 59. Full field list in `docs/appstore-metadata.md`.
4. **Host the privacy policy.** Apple requires a live URL. The text is in
   `docs/privacy-policy.md`; it needs to go up at `terraxtech.com/privacy`.
   The Next.js site at `~/terrax-website` is the likely home but has no git
   remote configured yet, so where it deploys is still an open question.
5. **Five screenshots** on the iPhone with hardware connected. Shot list is in
   `docs/appstore-metadata.md`.
6. **Upload** `terrax.ipa` via the Transporter app (drag and drop), then attach
   the build to version 1.0 and submit. The subscription must be submitted
   **with** the version, not separately.

All listing copy, keywords, the App Privacy answers (data not collected, which
is truthful: no backend, no analytics, no accounts), and the App Review notes
explaining that a reviewer without TERRAX hardware cannot exercise the control
screens, are written up in `docs/appstore-metadata.md`.

## 5. Smaller things worth knowing

- **The app reinstalls as a fresh icon** after the bundle id change, so saved
  devices reset once. Delete the old TERRAX TECH icon to avoid confusion.
- **Detection now matches on advertised service UUIDs, not just names.** Several
  accessories (the ambient light especially) advertise no name at all, and the
  scan list used to hide them entirely. Unnamed devices that advertise a service
  are now listed as "Unnamed device" and can be added manually.
- **Never claim service `0xAF30` for the ambient light.** The rock lights
  advertise it too; the ambient unit is identified by its advertised name.
- **A duplicate device entry can shadow a working one.** If an accessory shows
  "Bad state: ... characteristic not found", it was probably added under the
  wrong protocol family. Long-press it on the home screen, remove it, and re-add
  from a fresh scan.
- The verbose Bluetooth log is on in debug builds. `flutter run` (debug) prints
  every GATT operation, which is how the driver bugs in this session were found.
